# Markdown Wiki

普段は整形された文書として読み、編集したいブロックだけ Markdown 原文に切り替えて書ける wiki。

- 表示モード: 整形済みの本文上に文字単位のカーソル。矢印キー / `h` `j` `k` `l` / クリックで移動、ドラッグ / Shift+矢印で（ブロックをまたいだ）範囲選択。
- `Enter` / ダブルクリックで、カーソル位置を含む「編集単位」だけが Markdown 原文のテキストエリアになる。`Esc` で表示に戻る（変更は保持・自動保存）。
- Vim 風操作: 表示モード＝ノーマル、編集モード＝インサートとして、`h` `j` `k` `l` で移動、`i` でカーソル位置から、`a` で次の文字の後ろから編集を開始、`o` / `O` で下 / 上に新しい行を開いて編集（段落なら新しい段落、リストなら記号を継続）。上下移動は文書の端で止まります（ループしません）。最後の行でさらに `↓` / `j` を押すと、文末の下にある仮の空き行（「書き足す」の位置）にカーソルが移り、`Enter` / `i` / `a` / `o` でそこから新しい段落を書き始められます（`↑` で戻る）。ソースの末尾に改行がなくても使えます。編集中のテキストエリア内は通常の入力。本文末尾の「＋ 書き足す」でも新しい段落を書き始められます。
- 左サイドバーの「アウトライン」タブ（playground では左列）に見出しだけを一覧表示。クリックでその見出しへジャンプし（カーソルも移動、編集中なら確定してから移動）、スクロールに合わせて現在の節を強調。
- 本文の左端に編集ブロックごとの細い縦線を表示（段落は 1 行ずつ、表・リスト・コード・引用はブロック全体で 1 本。空行で番号が飛んで見えないよう数字は出さない）。クリックでそのブロックを選択（Shift+クリックで範囲）、URL が `#L12` / `#L12-L15` になり「リンクをコピー」で行のパーマリンクを取得。その URL を開くと該当行へスクロールして選択。
- 段落内の改行は個人設定で「改行として表示」（既定。ソースの 1 行＝表示の 1 行、リッチコピーは `<br>`）か「GFM のまま空白を詰める」（日本語どうしの間だけ空白を入れない）を選択。
- 複数行の編集: 範囲選択（ドラッグ / Shift+矢印 / 左端の縦線の Shift+クリック）してから `Enter` か `i` で、選択した行をまとめて 1 つの Markdown 編集欄で開く。表・リスト・コードなどにかかる場合はそのブロック全体を含め、段落は行単位で切り出す。選択範囲は編集欄の中でも選択されたまま。
- Emacs 風操作（macOS の表示モード）: `Ctrl+A` 行頭 / `Ctrl+E` 行末 / `Ctrl+F` `Ctrl+B` 1 文字 / `Ctrl+N` `Ctrl+P` 下・上の行（Shift 併用で選択を拡張）。全選択などのアプリ操作は `Cmd`。Windows/Linux では Ctrl がブラウザ操作と衝突するため無効。
- 上下移動は表示上の位置で行う（表の中でも上下のセルへ移動、連続した上下移動では元の列を保持）。
- 編集中の Enter は引用 `> `・リスト記号（番号は +1、タスクは `[ ]`）・表の行（同じ列数の空行）を次の行に引き継ぐ。記号だけの空行で Enter するとその記号を消して構文を抜ける。`Shift+Enter` は常に素の改行、`Cmd/Ctrl+Z` 1 回で自動挿入を取り消せる。コードブロック内や行の途中では働かない。
- 表示モードの取り消し: `Cmd/Ctrl+Z`（または `u`）で直前の編集（1 回の編集モードぶん、タスクのチェック切り替えも）を取り消し、`Cmd/Ctrl+Shift+Z` でやり直し。他のメンバーの更新や履歴からの復元が入ると、取り消し履歴はそこで区切る（他人の変更を巻き戻さないため）。
- `[[` 補完: 編集中に `[[` と打つとページ名の候補（⌘K と同じ一致方法、最近更新順）を表示。`↑↓` で選んで `Enter` / `Tab` で `[[ページ名]]` に。`Esc` 1 回目は候補を閉じるだけ。
- 操作一覧: `?` キーか画面下の「? 操作一覧」。画面下のヒントは短く、ページの操作（子ページ作成・名前変更・削除）は「…」メニューにまとめた。
- スマホ: 幅 760px 以下ではサイドバーを左から出るメニュー（☰）に、上部にページ検索ボタン。タッチではタップした位置に「編集」ボタンが出る（空のページはタップで書き始め）。編集は「完了」ボタンで終える。範囲選択時は「選択範囲を編集」も出る。キーボード向けのヒントは隠す。
- 変更履歴: ページ上部の「履歴」で版の一覧と差分を表示（自動保存で細かく増える版は、同じ人の 10 分以内の連続した保存を 1 回の編集としてまとめる）。「この版の変更」と「この版 → 現在の内容」を切り替えて比較し、「この版に戻す」でその内容を新しい版として保存（版は消さないので戻し直しも可能）。
- 画像: 編集中のテキストエリアへの貼り付け、または表示モードでの貼り付け / ドロップ（カーソルのあるブロックの下に新しい行を開いて挿入）でアップロードし、`![名前](/api/wikis/<id>/files/<id>)` を差し込む。アップロード中は仮の記法を入れておき、完了したら置き換えるので待たずに書き続けられる。PNG / JPEG / GIF / WebP / AVIF（中身のバイト列で判定、SVG は不可）、1 枚 10 MB まで。画像は wiki のメンバーだけが取得できる。
- ページを素早く開く: `Cmd+K`（Windows/Linux は `Ctrl+K`）またはサイドバーの「ページを開く…」で、ページ名の一部（大小文字無視・空白区切りの複数語・文字の飛ばし入力も可）から開く。該当がなければその名前で作成。編集中でも使える。
- GFM（表・タスクリスト・取り消し線・自動リンク等）+ 独自拡張 `[[ページ名]]`。
- Google ログイン、複数 wiki、オーナー / 編集者 / 閲覧者、メール招待。

## セットアップ

```sh
npm install
npm run dev          # API (PORT=3000, DEV_LOGIN=1) + Vite (http://localhost:5173)
```

`npm run dev` は開発用ログイン（任意のメールアドレスでログイン）を有効にします。Google ログインを使う場合は下記を設定してください。
ポート 3000 が使用中なら `PORT=3301 npm run dev` のように変更できます（Vite のプロキシも追従します）。

### Google ログインの設定

1. Google Cloud Console →「API とサービス」→「認証情報」→「OAuth クライアント ID を作成」（種類: ウェブアプリケーション）。
2. 承認済みのリダイレクト URI に `<APP_ORIGIN>/auth/google/callback` を登録（開発時は `http://localhost:5173/auth/google/callback`）。
3. OAuth 同意画面でスコープ `openid` `email` `profile` を設定。
4. `.env.example` を `.env` にコピーして値を設定（`.env` は git 管理外。実際の環境変数が優先）するか、環境変数で渡して起動:

| 変数 | 説明 |
|---|---|
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | OAuth クライアントの値 |
| `APP_ORIGIN` | ブラウザから見たオリジン（例 `https://wiki.example.com`）。リダイレクト URI と CSRF 検査に使用。`https://` なら Cookie に Secure が付く |
| `PORT` | API サーバーのポート（既定 3000） |
| `DATABASE_PATH` | SQLite ファイル（既定 `data/wiki.db`） |
| `DEV_LOGIN=1` | 開発用ログインを有効化（`NODE_ENV=production` では起動を拒否） |

### 本番

```sh
npm run build                     # dist/client を生成
APP_ORIGIN=https://wiki.example.com GOOGLE_CLIENT_ID=... GOOGLE_CLIENT_SECRET=... npm start
```

Node.js 24 以上が必要です（組み込みの `node:sqlite` を使用）。TLS は前段のリバースプロキシで終端してください。

## Cloudflare へのデプロイ

`worker/index.ts` が Cloudflare 用の入口です。サーバーのコード（`server/app.ts`）はそのまま共有します。

- 画面（`dist/client`）は Workers Static Assets が配信します（SPA フォールバック）。
- `/api/*` と `/auth/*` は 1 つの Durable Object が処理します。データは Durable Object 内蔵の SQLite に保存し、スキーマは Node 版と同じです。

```sh
npm run deploy                           # vite build && wrangler deploy
npx wrangler secret put GOOGLE_CLIENT_ID
npx wrangler secret put GOOGLE_CLIENT_SECRET
```

- `wrangler.jsonc` の `APP_ORIGIN` を公開 URL に合わせ、`<APP_ORIGIN>/auth/google/callback` を Google のリダイレクト URI に登録します。
- 開発用ログインは https のオリジンでは常に無効です。
- `npm run test:e2e:cf` で、同じ E2E テストを `wrangler dev`（ローカルの Durable Object）に対して実行できます。
- 全 wiki を 1 つの Durable Object で処理するので、小〜中規模向けの構成です。Durable Object の SQLite は 1 行 2 MB までなので、ページ本文は 60 万文字まで、画像は 1 MB ごとに分割して保存しています。

## テスト

```sh
npm test            # 単体・API テスト (vitest)
npm run test:e2e    # ブラウザ E2E (Playwright/Chromium。専用ポートでサーバーを自動起動)
```

## 技術構成と選定理由

| 層 | 採用 | 理由 |
|---|---|---|
| Markdown 解析 | micromark + mdast-util-from-markdown + GFM 拡張 | CommonMark/GFM 準拠で、全ノードにソース上のオフセットが付く。カーソル対応付けの土台 |
| 表示 | 自前の mdast → 仮想 DOM レンダラ | 各テキストに「1 文字ごとのソースオフセット」を持たせるため。React と HTML 文字列（リッチコピー）の両方に出力 |
| サニタイズ | hast-util-sanitize（GitHub 相当のスキーマ） | 生 HTML ブロックを安全に表示。インライン HTML は属性なしの書式タグのみ許可、URL は http(s)/mailto/相対のみ |
| フロント | React + Vite + React Router | 一般的で保守しやすい |
| サーバー | Hono (Node) + SQLite (`node:sqlite`) | 依存が少なくネイティブビルド不要。API は単体テストで直接呼べる |
| 共有コード | `shared/` をクライアントとサーバーで共用 | ページ名正規化、wiki リンク書き換え等を一箇所で |

## 設計の要点

### 表示位置 ↔ ソース位置（`shared/markdown/align.ts`, `src/editor/mapping.ts`）

文書全体を一度に GFM として解析し、テキストノードごとに **値とソースを先頭から同時に走査**して、表示される各文字がソースのどの位置から来たかを配列で得ます（バックスラッシュエスケープ、文字参照、引用やリストの継続行プレフィックス、インラインコードの改行などを考慮）。文字列検索は使わないため、同じ文章の繰り返しや装飾があっても正しく対応します。

表示中のカーソルはブラウザの Selection を真値とし（`Selection.modify` で文字・単語・行単位に移動）、その位置に独自のカーソルを描画します。DOM 位置は `span.r[data-r]` → 文字オフセット配列でソース位置に変換されます。

### 編集単位（`shared/markdown/units.ts`）

GFM のブロックとは別概念として、ソース上の行範囲で定義します。

| 内容 | 編集単位 |
|---|---|
| 通常の段落 | カーソルのあるソース 1 行（`**…**` などが行をまたぐ場合はそれを含むまで拡張） |
| 見出し | 見出し全体（setext は 2 行） |
| リスト | リスト全体（個人設定で「一項目とその配下」に切替可） |
| 表 / コードブロック / 引用 / HTML | 全体 |

編集中は他のブロックを編集開始時の解析結果のまま表示し続けるため、入力途中で空行やコードフェンスを打っても編集領域が閉じたりカーソルを失ったりしません。`Esc` で文書全体を再解析して表示を更新し、カーソルは対応するソース位置へ戻ります。切り替え時はカーソル行の画面上の位置を保つようスクロールを補正します。

### IME

`keydown` の `isComposing` / `keyCode 229`、Safari 向けに `compositionend` 直後の Enter を無視します。表示モードは非編集要素なので変換自体が始まりません。

### コピー（`shared/markdown/copy.ts`）

選択範囲をソース範囲に変換し、部分的に選ばれた構文の記号（`**`、`](url)`、コードフェンス、表のヘッダ行など）だけを補って Markdown を組み立てます。元の記法を保ったまま、選択部分だけで成立する Markdown になります。リッチテキストはこの Markdown を同じレンダラで HTML にしたもの。`Cmd/Ctrl+C` は HTML + プレーンテキスト、選択時のミニメニュー / 右クリックで 3 形式を選べます。編集中のコピーはテキストエリアの通常動作（ソース）です。

### リンク操作（`src/editor/linkPolicy.ts`）

クリック = 開く（ドラッグや Shift+クリックは選択のまま）、`Cmd/Ctrl+クリック` = 新しいタブで開く、`Alt/Option+クリック` = リンク文字の中にカーソル（`Alt+ダブルクリック` で編集）。カーソルがリンク内にあると小さな「開く / ページを作成」メニューが出ます（キーボード操作用）。未確定仕様のため設定を 1 ファイルに分離しています。

### 保存と競合

- 変更は即座にブラウザ内の下書き（localStorage）に保存し、0.8 秒後に自動保存。状態は「保存済み / 未保存の変更 / 保存中 / 保存失敗（再試行）/ 競合」で表示。
- 失敗時は指数バックオフで自動再試行＋手動再試行。再読み込みしても下書きから復元されます。
- サーバーは `baseVersion` による楽観的排他制御で、古い版からの保存を 409 で拒否（無言の上書きなし）。クライアントは共通の元の版との 3-way マージを提示し、重ならない変更は自動マージ、重なる場合は両方を残したまま編集して保存できます。全版を `page_revisions` に保存しています。

### wiki リンクと階層

`[[ページ名]]` / `[[ページ名|表示名]]`。テキストノードのみが対象なのでコード内では変換されず、`\[\[` のようにエスケープすれば無効化できます。ページ名は大文字小文字・全角半角を区別します（`LiSA` / `LISA` / `ＬｉＳＡ` は別ページ。正規化は Unicode NFC と空白の整理のみ。ページ名検索だけは英字の大小を無視）。ページ名の `/` が階層で、親ページなしで子ページを作れます（ツリーでは本文のない階層を斜体で表示）。改名すると旧名がエイリアスとして残るため、既存リンクは書き換えなくても切れません（任意で wiki 内のリンクを一括書き換えも可能）。

wiki には URL 用の**識別子**（半角英小文字・数字・ハイフン、2〜32 文字、全体で一意）があり、ページの URL は `/w/<識別子>/p/<ページ名>` です。作成時に指定でき（省略時は `w-xxxxxxxx` を自動採番）、オーナーは共有設定で変更できます。変更前の識別子はエイリアスとして残り、古い URL は新しい URL へ転送されます（他の wiki はその識別子を使えません）。wiki の id での URL も識別子の URL へ転送します。非メンバーには、識別子が存在するかどうかも分かりません（どちらも 404）。

オーナーは共有設定で wiki の**トップページ**を指定できます。ページ名のない wiki の URL（`/w/<識別子>`）を開くとトップページへリダイレクトします（未設定ならページ一覧）。トップページは id で保持するので改名しても外れず、削除すると未設定に戻ります。ページ一覧はサイドバーの「すべてのページ」（`/w/<識別子>?list`）から開けます。

### 権限

全 API で、セッションのユーザーと対象 wiki のメンバーシップをサーバー側で検証します（非メンバーには存在自体を 404 で秘匿、閲覧者の書き込みは 403）。招待はメールアドレス単位で、そのアドレスの Google アカウントでログインすると参加します。最後のオーナーは降格・削除できません。状態変更リクエストはカスタムヘッダと Origin を検査して CSRF を防ぎます。

## 既知の制約

- パーマリンク（`#L12`）は Markdown ソースの行番号です。本文が編集されると同じ番号が別の行を指すことがあります。ソフト改行で同じ表示行に並ぶ複数のソース行は 1 本の縦線にまとめます。

- リアルタイム同時編集はしていません（競合検出 + マージで対応）。他メンバーの更新は 15 秒ごとの確認で、ローカル変更がないときだけ自動反映します。
- 表示中の画像・水平線・HTML ブロックなどテキストを持たない要素には、ブロック先頭に相当する不可視のカーソル位置を 1 つ置いています。
- 表のセル単位の Markdown コピーは「該当する行全体＋ヘッダ」になります。参照形式リンクの一部コピーはインライン形式に変換します。
- インライン HTML は属性なしの書式タグ（`<b>` `<kbd>` 等）のみ表示し、それ以外は除去します。
- `Selection.modify` を利用しているため、Chromium / Safari / Firefox の現行版が前提です。E2E は Chromium のみで実施しています。
- IME の E2E は Chrome DevTools Protocol による擬似変換で検証しています（実際の OS の IME での確認は手動が必要）。
- 本番の Google ログインは実クライアント ID での疎通確認をしていません（トークン交換部分はモックでテスト）。
